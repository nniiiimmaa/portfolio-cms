# Entity Relationship Diagram (ERD)

# 1. Introduction

## 1.1 Purpose

This document describes the Entity Relationship Diagram (ERD) of the Portfolio Management System.

The ERD represents the logical structure of the application's database and illustrates how data entities relate to one another. It serves as the primary reference for database design, implementation, maintenance, and future expansion.

The database has been designed using relational database principles to provide high data integrity, minimal redundancy, and efficient data retrieval.

---

## 1.2 Scope

The Entity Relationship Diagram covers all business entities required by the Portfolio Management System, including:

* User Management
* About Information
* Professional Experience
* Projects
* Project Types
* Project Statuses
* Project Images
* Education
* Certifications
* Skills
* Skill Categories
* Testimonials
* Contact Information
* Social Links
* Contact Messages
* Languages
* Translation Tables

System infrastructure tables generated by Laravel (such as cache, jobs, sessions, and failed_jobs) are excluded from the conceptual ERD because they do not represent business entities.

---

## 1.3 Objectives

The database model has been designed to achieve the following objectives:

* Maintain data integrity
* Reduce data redundancy
* Support multilingual content
* Enforce referential integrity
* Simplify future maintenance
* Improve query performance
* Support application scalability

---

## 1.4 Design Methodology

The database follows a relational design based on Entity Relationship Modeling (ERM).

Key design principles include:

* Entity separation
* Third Normal Form (3NF)
* Foreign key constraints
* Cascading relationships
* Translation table architecture
* Modular entity organization

This approach ensures that each business concept is represented by an independent entity while preserving logical relationships between them.

---

## 1.5 ERD Overview

The Portfolio Management System database consists of several interconnected modules.

The primary entity groups include:

* Authentication
* Portfolio Content
* Localization
* Communication
* Portfolio Classification
* Administrative Content

Most content entities implement a translation architecture in which multilingual information is stored in dedicated translation tables associated with the central **languages** table.

This structure enables unlimited language support while maintaining a normalized database schema.
